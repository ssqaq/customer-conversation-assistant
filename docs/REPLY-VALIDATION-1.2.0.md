# 1.2.0 回复规则验证与回测计划

日期：2026-09-10。1.2.0 增加输出模式锁定、截图与微信合并转发边界，并把多模型回测固定成可重复的验收流程。

## 硬不变量

- “只要正文”只返回可发送正文，不混入标题、分析、来源、评分或第二版本。
- “只要一句”保留用户要求的全部事实；一句按语义判断，不为了凑短删除条件。
- “只做分析”不生成客户可发送正文；“给多个版本”只给用户指定数量。
- 截图中的金额、电话、日期、姓名或状态看不清时，明确指出缺口，不猜、不声称完成 OCR。
- 合并转发有明确标签时保留原说话人、时间和批次；没有可靠归属时先澄清“我”指谁，不把转发者自动当成原聊天发言人。
- 普通文章没有客户背景时，不套用客户档案、售后或跟进模板。

## 最小回归场景

| 编号 | 场景 | 通过条件 |
|---|---|---|
| R1 | 同一报价材料要求“只要正文” | 仅正文，保留姓名、金额、币种、日期、暂定和未批准条件 |
| R2 | 同一会议材料要求“只要一句” | 一句包含时间、渠道和准备事项，不输出项目符号或解释 |
| R3 | 退款记录要求“只做内部分析” | 只给事实、推测、待确认和来源，不写客户话术 |
| R4 | 明确要求三个版本 | 恰好三个版本，事实完全一致，无第四版和总评 |
| R5 | 清晰截图含说话人、时间和订单号 | 保留可见来源，不把截图内容写成无来源事实 |
| R6 | 截图金额或说话人模糊、被裁剪或无法打开 | 标出具体缺口，只分析可读部分，请求原图、局部图或转录 |
| R7 | 合并转发有“客户李梅/我方小周”标签 | “我”和“对方”按原聊天标签归属，保留批次和顺序 |
| R8 | 合并转发无导出方或嵌套转发 | 先问最小归属问题，不确定责任、退款状态或当前用户身份 |

## 多模型执行格式

同一版本 Skill、同一套输入文本、同一附件字节哈希和新会话，分别在至少三个实际可用模型上运行 R1-R8。记录模型名称、版本、日期、输入哈希、附件哈希、原始输出、硬不变量判定和失败原因。事实值、条件、输出模式、不可读不猜和说话人归属是硬判定；自然度、长短和口吻只做观察，不用一个模型通过抵销另一个模型失败。

本轮已用 `gpt-6-astra` 完成 5 个代表场景的独立回测，结果记录在工作区 `work/model-eval-astra.md`；它覆盖正文模式、一句话、截图不清、合并转发归属和普通文章边界。另两个候选模型执行端分别返回服务不可用（503）和模型不可用（404），因此三模型完整回测仍未完成，不能把单模型结果写成多模型通过。后续获得可用模型后，按本文件补跑，不修改旧结果。

## 截图与合并转发的实际限制

本 Skill 不自带 OCR、微信读取或 WorkBuddy 连接。能否读取截图和合并转发取决于当前环境的实际输入能力；不可读时必须报告缺口。纸面规则通过不等于真实截图或真实微信导出已经验证。
